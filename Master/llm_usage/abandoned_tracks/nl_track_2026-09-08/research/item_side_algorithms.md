## 0. Two analytical results that reorganise the menu (derived here, not from the literature)

Both follow from the fixed things in this programme: **categorical inputs with a fixed vocabulary**, and a **cosine layer downstream**, which is invariant to positive scaling of q_i.

**(R-a) Any per-token nonlinearity is a re-parametrisation of the free row.** For a token (field value) v with embedding e_v, a learned map φ(e_v) — an MLP, a gate, a value projection W_V e_v, a Deep-Sets φ — takes exactly one value per vocabulary entry, so φ(e_v) =: e′_v is again a free table of size V·d. Deep Sets ρ(Σ_t φ(e_t)) (Zaheer 2017) over a fixed vocabulary is therefore "linear sum, then ρ": the only nonlinearity that is *not* already in the function class of Σ_t e_t is ρ (the post-sum map) or an interaction *between* tokens. This is plan §0's "for a single categorical field a free row is already the most general function" restated for encoders; it applies equally to hm fields and ml-1m tokens.

**(R-b) Token-only attention pooling followed by a cosine layer is a re-parametrisation of the noid arm.** MIL attention (Ilse 2018) scores each instance from itself: s_t = wᵀ tanh(V e_t) (gated: wᵀ[tanh(V e_t) ⊙ σ(U e_t)]), then q = Σ_t softmax(s)_t e_t = (Σ_t exp(s_t) e_t) / Σ_t exp(s_t). Over a fixed vocabulary s_t is a per-token scalar β_v := exp(s_v) > 0, and the softmax denominator is a positive scalar that the cosine ignores. Hence cos(q, p_l) = cos(Σ_t β_t e_t, p_l) = cos(Σ_t e″_t, p_l) with e″_v = β_v e_v — a **row-norm re-scaling of the free table**, which the table already has. Same for Set Transformer PMA with a single seed and no self-attention block before it (score = seedᵀ W_K e_t, value = W_V e_t: token-only, linear), and for ACF's component-level attention when the query is not the candidate. What survives as *genuine* nonlinearity for a bag under a cosine layer is exactly: (i) **token × token products** (bi-interaction, FM-type), (ii) **context-dependent scores** (self-attention / ISAB before pooling: s_t depends on the other tokens), (iii) a **post-sum map ρ**. Consequences:
- On the **noid** arm, MIL/gated/PMA(token-only) attention can move accuracy only through optimisation/inductive bias, not function class; a gain there is a training-dynamics finding, not a composition finding. Its explanation object is nevertheless attractive: β_v is a printable **learned per-token weight table** (a learned IDF; compare SIF's a/(a+p(v)) — Arora 2017 §1, which is the same object with a fixed formula).
- On the **ids** arm the normalisation *does* matter: Σ_t softmax(s)_t e_t + e_ID fixes the bag's mass relative to the ID row (P3 norm handover), whereas the raw sum lets a 72-token bag swamp e_ID and a 3-token bag hand the item to it. Mean-vs-sum is therefore an ids-arm knob and an ID-share instrument, not a noid-arm capacity change.
- The plan's SP2(a) "attention pooling = RETAIN form, nonlinear weights on linear rows" is correct as an *explanation regime* but, under the cosine, the weights are per-token constants — the faithfulness question (Jain & Wallace 2019, E4a; Wiegreffe & Pinter 2019, E4b) collapses to "is the learned β_v table meaningful", which is a much easier test (compare against SIF/IDF weights; frozen-weight retrain as in AFM §5.3).

The bag-size channel is likewise two channels: (1) **norm** ‖Σ_t e_t‖ ∝ n — invisible to the cosine itself, visible only through the ID mix (ids arm) and any norm-sensitive regulariser; (2) **direction** — the sum of n tokens drifts toward the common component μ as n grows (the P2 collapse-toward-μ mechanism; Arora 2017's "common component removal" and Mu & Viswanath 2017's all-but-the-top exist for exactly this), which the cosine *does* see and which makes long-bag movies look like "the generic movie". Softmax/mean weighting fixes (1) and not (2); centring (fI′'s U2b field-mean centring) fixes (2). Products (bi-interaction) *feed* both: n(n−1)/2 pair terms, and the pair-sum drifts toward the mean pair direction.

**The "few fields + ID row ⇒ conjunctions add nothing" result.** No paper states it as a theorem; it is the composition of four verified facts: (1) FM already expresses any PSD pairwise interaction with k large (Rendle 2010 §III.A.2) and subsumes SVD++/biased MF — the family's classic gains are ID-row gains; (2) the item ID is the *maximal* conjunction (it determines the full tuple), so in the ids arm every pair row is in the function class of e_ID (plan §0 absorption, vault 2026-07-12_1739); (3) the local ID-row probe (2026-09-07, section A) found R² ≈ 0 of the trained e_ID on up to 5,000 pair columns — the model did not spend the free row on conjunctions; (4) Zhu et al. 2021 (CIKM; arXiv 2009.05794: 24 models, 7,000+ runs) find that "with sufficient hyper-parameter search … many deep models have smaller differences than expected", and Rendle et al. 2020 (arXiv 2005.09683) that MLP similarity is hard to train to even match a dot product — so published interaction-module gains, all measured with ID rows present, are small and fragile to begin with. Zhang et al. 2022 (CIKM; arXiv 2209.06053) add that deep CTR models with high-cardinality sparse ID features one-epoch-overfit — the ID row is the overfitting engine, not the interaction module. **For hm the whole of (A) is bounded above by tuple-ID − fI-noid**, a number about to exist; every row of the table only decides *how* to spend that gap if it is non-zero.

## 3. (C) Recommendation — per dataset, 2–3 forms worth a light `/design-candidate` cycle

Ground rules applied: honest bed = noid arm; every form gets its **linear twin** (same units, no nonlinearity) and its **dot twin** (same composition, `lightfm_tags`-style plain dot) so the 2×2 of plan §3 separates H_comp from H_geo; noise bar 2 × 0.0026 HR@10; any positive re-run at 100 trials before belief (the fI ml-1m 30-vs-100 flip). R8: one idea per candidate, no stacking. S5: every form below is lookups plus at most an elementwise product or a d×d MLP — pipeline profile preserved.

### 3.2 ml-1m (bags; near-unique bags as covert IDs)

**Ceiling.** With 3.8 % twins the tuple-ID arm on ml-1m is, up to 118 twin classes, a free row per item — i.e. `item_proto` (noid, dev tier) is the ceiling of every within-bag composition; the `ml-1m_tuple` run only confirms this. Every (B) form is bounded by item_proto − fI-noid, and a wide encoder that closes that gap on near-unique bags has to be *shown* not to be memorising the bag as an item ID (tests in the table).

**Linear first.** SP2's premise — "every token weighs 1 created the bag-size channel" — is answered before any nonlinearity by a zero-parameter linear change.

Demoted on ml-1m: token-only attention pooling (MIL, gated, PMA-1-seed) — a re-parametrisation under the cosine (R-b); keep only as the *diagnostic* "learned β_v vs SIF β_v" comparison if rank-1 works, because the learned IDF table is a nice explanation object. Set Transformer with ISAB: build only as the 2×2 ceiling cell if rank-2/3 leave a gap, never as the candidate. Explicit token-pair rows: vocabulary explosion + covert ID. ACF/TEM/AARM-type user-conditioned attention: target-conditioning, SP9's business.

### 3.3 What the literature does *not* give us (state in the chapter)

1. No verified paper reports an interaction module's gain **without** an ID field on categorical recsys data; the FM-family evaluations (NFM §4.1.1, AFM §5.1) all have user-ID + item-ID fields, and the CTR benchmarks are ID-dominated. The one ID-free additive result (GA²M, Lou 2013) is tabular, not recsys. Our noid arms produce a number the literature lacks.
2. The re-parametrisation results (§0 R-a, R-b) are not in the attention-pooling papers because none of them sits under a cosine layer over a fixed vocabulary; they must be stated and unit-tested (attention arm vs row-rescaled linear arm should reach the same training loss up to optimisation noise).
3. Gains of the size the interaction literature reports (AFM: 8.6 % relative RMSE; NFM: 7.3 %) are RMSE on regression with IDs; nothing suggests they transfer to HR@10 on a noid item vector under a frozen layer. Treat 2 × 0.0026 as the bar and the tuple-ID gap as the ceiling.
